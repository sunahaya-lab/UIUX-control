# ゲームUI：4条件の探索比較

[4条件の画面を開く](https://sunahaya-lab.github.io/UIUX-control/experiments/game-four-conditions/)

Aはスキルなし、BはUIUX-control本文とUX方針のみ、Cはgame-ui-frontend本文のみ、DはB/Cの両方。リンク先の別スキルや参照への追跡は禁止しました。全条件で会話履歴なし、同じ依頼文と描画資産、実装1回＋構文確認。納品後のコード・デザインは未修正です。

同じ親セッション・同じエージェント種別・モデルと推論設定の上書きなし。モデルの既有知識や共通の実行指示・スキル一覧まで除去したものではなく、指定したスキル本文を明示的に読み適用する条件の比較です。実際の計算量、トークン数、所要時間を揃えた実験ではありません。公開依頼文ではローカルパスだけを記号化しています。各エージェントから許可ファイル以外を読んでいない旨の報告を受けています。

## 共通の確認

- PC1440×1000相当の初期表示を撮影し、文書高とジャンプボタン位置を測定。
- 修復1回でシールド3/3・残数0、ブースト1回で88%・残数1。
- 結果見出しとスコア、再試行、停止見出しを確認。
- 設定の音量60→61を確認。
- スマホ390×844相当の初期表示、横幅、ボタン位置を記録。
- 描画素材のバイト一致。納品時の内容をLF改行へ正規化したSHA256をgeneration-hashes.jsonに保持（環境による改行変換を除外）。

## 観察と限界

A/Cの停止・終了見出しは比喩的、B/Dは状態を直接表す表現でした。PCの文書が表示高に収まったのはC/D。Bでも鉱石などの数値の重複が残りました。Dはミッション詳細を開く構成です。

各1本の観察で、因果効果・寄与率・優劣・相乗効果の証明ではありません。文書高やクリック数だけで品質を評価していません。人間の理解度や操作時間は未測定です。次の段階では同条件で複数回生成し、条件を隠した課題遂行評価が必要です。
