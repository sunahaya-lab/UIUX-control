# 素材制作と状態演出をつなぐ

豪華な画面を依頼されたときは、構図とともに素材制作を計画する。imagegenを最後の挿絵追加だけに使わず、何を生成するか、美術をどう揃えるか、選択時にどう変わるかまで設計する。局所的な文言変更や素材が不要な画面には、この工程を一律に追加しない。

## 1. 共通の美術仕様を決める

- 画面で達成すること、見せたい主役、感じてほしい魅力を起点にする。色だけでなく、輪郭・形の規則、材質、線の太さ、描き込み、光、遠近感、文字との関係を短く定める。生成担当と実装担当で同じ仕様を使う。
- 既存の採用素材・ブランド仕様があれば基準にする。基準がない場合は代表となる一枚や部品で方向を確かめてから関連素材を展開する。すべての背景・枠・人物を別々の方向で生成して、あとから色補正だけで揃えようとしない。
- 基準画像には「画風・材質の参照」「維持するキャラクター」「編集対象」などの役割を明記する。引き継ぐ特徴と変更する特徴を区別し、無関係なレイアウトや文言まで継承しない。

## 2. 生成前に出力リストを作る

制作範囲に応じた短い表でよい。小さな依頼に巨大な素材台帳を作らない。必要な素材を判断して列挙し、以下の例を全部作るチェックリストとして使わない。

| 候補 | 担う役割 | 制作・実装の分担例 |
|---|---|---|
| キャラクター立ち絵・肖像 | 主役、愛着、識別 | imagegenで絵を用意し、名前・能力値・選択状態は実装で重ねる |
| 背景・一枚絵 | 場所、空気感、構図 | 主な内容の配置を指定して生成。読む場所との競合は合成後に確認 |
| 枠・紙・装飾片 | まとまり、材質、世界観 | 絵柄が必要なら透過素材。単純な形や可変サイズはCSS/SVGも候補 |
| 紋章・封印・状態マーク | 識別、決定の印象 | 慣用アイコンを優先。固有の絵が必要なものだけ生成し、意味をラベルで支える |
| 選択・決定の演出素材 | 操作への反応、区切り | 必要ならマスク・光・印の絵を生成。時間変化と入力への追従は実装で制御 |

各項目に、素材ID・使用場所・役割・既存利用/生成/コードで作成の別・必要な比率と表示寸法・透過の要否・基準画像・切り取りや伸縮の条件・対応する状態・出力先を記す。生成指示には必要な項目だけ渡す。画像ツールが指定寸法を厳密に出せると仮定せず、返った寸法を確認して配置と合わせる。

人物なら顔や手が切れない範囲、枠なら文字を入れる領域と伸ばしてよい部分、背景なら重ねる内容の位置を決める。色反転だけで作れる選択状態まで別画像として量産しない。作る必要のないものも分担表で分かるようにする。

## 3. imagegenと実装の境界を決める

- 絵・写真・有機的な材質等、新しいビットマップが必要なら、利用可能なimagegenスキルを読み、その手順で生成・編集する。この資料は生成ツールの呼び出し仕様や権限を置き換えない。
- imagegenがない環境では、利用可能な既存素材やコード表現を使うか、出力リスト・生成指示まで作って不足を明示する。別の有料APIへの自動切替や、未生成素材の納品扱いはしない。仕様整理だけの依頼なら生成は始めない。
- 操作ラベル、名前、数値、エラー、可変文言は原則として実装側の文字にする。完成画面を一枚絵に焼き込み、その上に透明ボタンを貼ってUI実装の代わりにしない。固定の題字や表現文字を画像にする場合も、意味を取得できる代替と狭幅時の表示を用意する。
- 枠や装飾は内容と切り離し、描画領域と押せる領域を分けて扱う。画像一枚の比率に合わせるために文字を縮めず、必要なら伸縮可能な枠、コードの下地、別の構図を選ぶ。
- 生成した素材は実際の画面へ配置して検収する。基準との色・輪郭・材質の一致だけでなく、顔や名前を隠さないか、状態表示と紛らわしくないか、読み込み中や失敗時に操作を失わないかを見る。採用素材と生成指示をプロジェクト内に残す。

## 4. 状態と演出の表を作る

必要な状態だけを選び、「何が変わるか」「何を保つか」「次の入力を受けるか」「動き軽減時」を決める。ホバー・フォーカス・選択・決定を同じ状態として扱わない。

| 状態・操作 | 表現の候補 | 保つこと |
|---|---|---|
| ホバー／キーボードフォーカス | 輪郭や面の変化、短い持ち上がり | 選択確定とは区別。ホバーできなくても意味が分かる |
| 選択 | 面と文字色の反転、選択マーク、関連詳細の更新 | 選択状態は演出後も残る。色以外でも区別し、フォーカスも見失わせない |
| 押下／受付 | 押し込み、短い反応 | 入力受付をすぐ示す。演出だけ先に成功を告げない |
| 決定／完了 | 印が押される、一度だけ輪郭が広がる、結果へ視線を渡す | 実際の成功後に結果を示す。名前・値・次の操作を覆わない |
| 取消／戻る | 来た方向への短い遷移、選択位置へ戻す | 入力・選択・位置と適切なフォーカスを保つ |
| 無効／処理中／失敗 | 状態に応じた表示と必要な理由 | 違いを区別。理由や復帰方法を薄い装飾扱いにしない |

反転は選択表現の一例であり、全画面への必須規則ではない。人物画全体まで機械的に反転したり、反転後の文字を読みにくくしたりしない。演出は操作結果へ注目を集めた後、読むことや次の操作を邪魔しない位置と強さに落ち着かせる。

## 5. 心地よさは反復操作で調整する

- 「入力への即時反応→状態の移行→落ち着いた表示」を分ける。常に光らせたり全要素を順番に登場させたりすることを豪華さの条件にしない。動かす対象と動かさない対象の関係でリズムを作る。
- 長さ・開始のずれ・加減速・重なり・入力受付を、対象操作の頻度に合わせて調整する。仮値の例は選択120ms、詳細切替220ms、決定280ms。ただし推奨規格や万人の快適値ではなく、実表示で調整するための出発点にすぎない。
- 高頻度の選択では待ちを作らず、次の入力で途中の演出を更新・中断できるようにする。古い対象の画像・効果・結果をキューに溜めない。低頻度の場面転換では余韻を使えても、毎回の反復操作へ同じ長い演出を持ち込まない。
- 素早い連続選択、行き戻り、長い名前、画像未読込、音なし、動き軽減で試す。フレーム落ち、入力の取りこぼし、チラつき、位置の飛び、二重確定を確認する。動きを減らしても選択と完了が分かるようにする。
- 「人間に心地よい」は生成担当の宣言で確定しない。技術的に操作が通ったこと、観察した遅延、利用者が快適と判断したことを分けて記録する。

素材リスト・美術仕様・状態表を実装へ引き継ぎ、採用素材と画面での検収結果まで対応させる。素材数やアニメーション数を成果の指標にしない。
